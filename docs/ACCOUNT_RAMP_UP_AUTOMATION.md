# 小红书账号冷启动与稳定运营流程（自动化边界版）

## 1. 文档目的

本文把常见的“养号”经验改写为一套可审计、低 Token、可接入当前设备矩阵的账号冷启动流程。

这里的“养号”仅指：完成账号与设备建档、持续开展垂直主题研究、辅助原创内容规划、记录运营结果，并由人工完成资料设置、互动和发布。它不表示伪装真人、制造虚假活跃、批量互动或规避平台风控。

视频材料中的“一机一号一网络”“固定互动数量”“设备四清”“切换 IP/OAID”“模拟移动轨迹”等属于经验性说法，不是平台公开保证。本项目不把这些说法做成自动执行规则。

## 2. 方案结论

- 每个账号使用唯一的本地 `accountAlias`，并与一台已标定的 `deviceAlias` 建立人工确认的关系；真实账号和设备标识不进入 Git。
- 效卫用于投屏、查看单机画面和人工接管；ADB 用于经过后验验证的只读操作。
- Hermes 只负责按计划投递任务；研究执行器负责预检、设备分配、预算、幂等、熔断和结果归档。
- 自动化仅执行打开 App、搜索、读取公开页面、在已识别容器中滚动、采集公开内容和生成研究结果。
- 头像、昵称、简介、登录验证、关注、点赞、收藏、评论、私信、购物和发布均由人工决定和执行。
- AI 只用于新主题策划、未知页面辅助识别和研究结果分析；页面稳定且主题有缓存时允许 0 次模型调用。
- 账号阶段按可验证成果推进，不以随机停留时间、机械互动数量或“像真人”作为完成条件。

## 3. 从参考材料中保留与排除的内容

| 参考建议 | 本流程处理方式 | 原因 |
| --- | --- | --- |
| 一台设备对应一个账号 | 保留为本地运营映射 | 便于责任、日志和人工接管，不把它宣称为平台风控规则 |
| 设备性能、系统版本和来源检查 | 保留为设备健康建议 | 降低卡顿、崩溃和维护成本 |
| 使用稳定、合法取得的网络 | 保留 | 保证连接质量，不用于伪造位置或规避限制 |
| 前期浏览、搜索、理解垂直领域 | 改为有主题和预算的只读研究任务 | 可验证、可复现、不会产生外部互动 |
| 逐步开始互动 | 改为人工审核候选后自主决定 | 自动互动容易误操作，也可能违反平台规则 |
| 选题表、对标内容和数据分析 | 保留 | 用于原创选题研究，不复制内容 |
| 固定点赞、评论、关注数量 | 不自动化，也不作为阶段门槛 | 避免机械行为和虚假互动 |
| 随机停留、模拟移动/通信/消费 | 排除 | 不伪装真人或制造虚假轨迹 |
| 恢复出厂、重置 OAID、切 IP 复活账号 | 排除 | 不通过设备或网络身份操作绕过平台处置 |
| 私域导流和批量触达 | 不进入本流程 | 属于外部通信，需要另行进行平台规则和合规审查 |

## 4. 角色与权限

| 角色 | 职责 | 可以操作手机 | 不得执行 |
| --- | --- | --- | --- |
| Hermes | 定时投递已批准的任务 JSON | 否 | 生成随机行为、绕过预算或直接发 ADB 命令 |
| 研究执行器 | 预检、只读导航、采集、去重、归档 | 仅只读动作 | 任何互动、发布、登录或系统身份变更 |
| 主题策划 Agent | 根据种子词、搜索建议和缓存生成查询计划 | 否 | 操作设备、生成互动动作 |
| 研究分析 Agent | 聚类、排序、总结内容空缺 | 否 | 复制原文或决定发布 |
| 页面恢复 Agent | 在本地规则失败后判断页面类型和语义目标 | 否 | 返回坐标、处理敏感页面或直接点击 |
| 运营人员 | 建档、资料设置、内容审核、互动和发布 | 是，单机人工操作 | 群控同步执行外部互动 |
| 维护人员/Codex | 修复页面规则和脚本 | 仅经授权诊断 | 自动修改账号、网络或设备身份 |

## 5. 账号状态机

```text
draft
  -> device_ready
  -> profile_ready
  -> topic_learning
  -> content_preparation
  -> steady_operation

任意阶段
  -> human_required
  -> paused
  -> retired
```

状态说明：

- `draft`：账号尚未完成本地建档。
- `device_ready`：设备别名、分组、版本和只读能力已通过预检，并且该设备已独立通过 Hermes 只读能力验收。
- `profile_ready`：人工确认账号归属、登录状态和基础资料，无自动化资料修改。
- `topic_learning`：按垂直主题执行只读研究，建立主题词和候选内容缓存。
- `content_preparation`：AI 与人工根据研究结果准备原创选题和素材清单。
- `steady_operation`：按固定研究节奏复用缓存，人工决定内容发布和互动。
- `human_required`：出现中文输入失败、页面不确定、登录/验证码/风险提示或需要人工决策。
- `paused`：运营人员主动暂停，Hermes 不再投递该账号的任务。
- `retired`：账号停止使用；不得通过改设备身份或新建映射绕过平台处置。

只有人工可以批准 `profile_ready`、`content_preparation` 和 `steady_operation` 的阶段变更。

## 6. 本地建档与设备准备（P0）

### 6.1 设备健康建议

- 优先使用性能足以稳定运行当前 App、仍能取得系统安全更新、来源可核验的原装设备。
- 不使用 Root、解锁或经过不明修改的设备执行正式任务。
- 每台设备独立标定小红书版本、分辨率、DPI 和页面覆盖规则；不共享主控坐标。
- 设备别名和账号别名只保存在被 Git 忽略的本地配置或 `data/` 中。
- 正式研究工作单元中，一台设备连续两次设备失败后立即隔离，不把任务扩散到其他设备；主题发现阶段单独记录失败。

“8+128G”可以作为采购和维护参考，但不是本流程的技术硬门槛；实际门槛是预检、页面稳定检测和监督式验收能否通过。

### 6.2 网络原则

- 使用合法取得、稳定、可维护的普通网络连接。
- 网络规划只解决可靠性、带宽、故障隔离和资产归属问题。
- 不自动开关飞行模式、重启网络设备、切换公网 IP、伪造位置或操纵设备标识。
- 平台限制、验证码或风险提示出现时停止并转人工，不尝试换网重试。

### 6.3 本地账号档案

在被忽略的 `data/accounts/<accountAlias>/profile.json` 中保存以下状态。`.\xhs.cmd ramp run` 会读取并严格校验该档案，再生成普通只读研究任务：

```json
{
  "schemaVersion": 1,
  "accountAlias": "account-01",
  "deviceAlias": "device-01",
  "deviceGroup": "account-01-research",
  "phase": "topic_learning",
  "primaryTopic": "夏季通勤穿搭",
  "topicPool": ["夏季通勤穿搭", "通勤鞋", "办公室穿搭"],
  "automationPolicy": "research_read_only",
  "interactionPolicy": "human_final",
  "paused": false,
  "phaseApproval": {
    "phase": "topic_learning",
    "approved": true,
    "approvedAt": "2026-07-14T00:00:00+08:00"
  }
}
```

不得记录密码、短信验证码、真实手机号、Cookie、Token、真实设备序列号或联系人信息。

## 7. 分阶段流程

日期只是运营观察窗口，不是风控技巧；是否进入下一阶段取决于验收结果和人工批准。

首次正式投递前，先按 [Hermes 小红书只读能力验收流程](HERMES_CAPABILITY_ACCEPTANCE.md) 在一台人工批准的设备上完成最小预算验收。验收覆盖所有允许的只读动作；点赞、收藏、关注、评论发送、私信和发布只验证安全门会拒绝，不实际操作。

### 阶段 A：第 1 天，建档与人工初始化

自动化：

1. 清点在线设备并验证唯一别名和分组。
2. 检查 App 版本、页面规则版本和只读输入能力。
3. 打开 App，读取当前页面状态；如果是登录、验证码、权限或风险页面，立即停止。
4. 生成预检报告，不做搜索和互动。

人工：

1. 确认账号为合法持有并完成必要的登录或身份验证。
2. 设置真实、准确且符合平台规则的头像、昵称、简介等资料。
3. 选定一个主要内容领域和 3 至 10 个种子主题。

进入下一阶段的条件：设备预检通过、账号主页由人工确认、没有登录或风险挑战。

### 阶段 B：第 2 至 3 天，基础主题学习

每天最多投递 1 个只读研究任务：

- 来源：`search`、`suggestions`。
- 查询数：最多 2 个。
- 候选笔记：最多 5 条。
- 结果滚动：每个查询最多 2 次。
- 评论模式：`none`。
- 前 3 天不采集评论元数据，以降低页面转场和操作复杂度，先验证主题搜索链路本身稳定。
- AI：主题有缓存时 0 次；无缓存时主题策划最多 1 次。

自动化产物：真实搜索建议、候选标题、公开作者、媒体类型、主题词缓存和设备事件日志。

人工检查：候选是否与目标领域相关、是否存在不适合继续研究的敏感方向、主题是否需要收窄。

进入下一阶段的条件：至少 2 个任务安全完成、没有外部互动、没有设备隔离或敏感页面。

### 阶段 C：第 4 至 7 天，垂直内容研究

每天最多投递 1 个只读研究任务：

- 来源：`search`、`suggestions`、`recommended`；热搜入口存在时可增加 `trending`。
- 查询数：最多 3 个。
- 候选笔记：最多 8 条。
- 每个查询结果滚动：最多 3 次。
- 评论模式：默认 `metadata`，全任务最多打开 2 个评论面板。
- AI：候选达到 5 条时，可调用 1 次研究分析；总自动模型调用仍受任务上限约束。

自动化不安排点赞、收藏、关注或评论配额。运营人员若认为某条公开内容值得互动，必须从人工审核队列选择单条候选，关闭群控同步，只显示一台手机后自行决定和执行；该动作不作为阶段完成条件。

进入下一阶段的条件：形成稳定主题词池、候选去重有效、人工确认研究结果可用于原创内容策划。

### 阶段 D：第 8 至 30 天，内容准备与人工发布

自动化每个运营日完成以下支持工作：

1. 从 30 天主题缓存、搜索建议和近期研究结果中提出候选主题。
2. 采集有限数量的公开候选，提取共同问题、内容缺口和公开数据特征。
3. AI 在预算内生成选题分组、相关性排序和原创内容理由。
4. 输出人工选题表，不自动生成或搬运整篇笔记。
5. 记录人工采用、搁置或拒绝的候选，供下一次研究去重。

人工负责：事实核查、原创表达、版权检查、敏感词检查、最终编辑和发布。发布频率由内容质量、实际运营能力和平台规则决定，不由脚本强制递增，也不自动执行“一天一条”或“一天两条”。

### 阶段 E：30 天后，稳定运营

- 按账号垂直领域维护主题缓存和排除词。
- 每周生成一次主题回顾：已覆盖主题、内容缺口、重复候选、人工采用率和失败原因。
- 页面稳定时优先运行 0 模型或 1 次结果分析的低 Token 流程。
- 运营人员定期复核账号资料、内容质量、版权和平台通知。
- 任何账号处罚、异常验证或风险提示都进入人工处理，不通过换设备、换网络或改标识继续执行。

## 8. 每日自动流程

```text
Hermes 到达计划窗口
  -> 读取本地账号阶段和 paused 状态
  -> 生成唯一 taskId
  -> 研究任务 Schema 校验
  -> 单设备组预检
  -> 页面安全检查
  -> 只读主题研究
  -> 跨查询去重
  -> 可选 AI 分析
  -> 写入本地 JSON/JSONL
  -> 生成人工审核队列
  -> 结束，不执行互动或发布
```

Hermes 的唯一账号级入口是：

```powershell
.\xhs.cmd ramp run `
  --profile data/accounts/<accountAlias>/profile.json `
  --sequence 1
```

完整调用和阻断规则见 [Hermes 账号冷启动研究执行手册](HERMES_ACCOUNT_RAMP.md)。

调度规则：

- 使用明确的运营窗口和研究预算，不使用随机停留或随机互动。
- 同一 `taskId` 重复投递时直接返回原结果。
- 每个账号同时最多有 1 个活动任务，避免同设备并发。
- 多设备之间可以并行研究，但每台设备内部严格串行。
- 账号处于 `human_required`、`paused` 或 `retired` 时不得继续投递。
- Hermes 不直接接收真实账号、手机号或设备序列号。
- 每日任务 ID 使用 `ramp-<accountAlias>-YYYYMMDD-NN`；`accountAlias` 只使用本地不透明别名，`NN` 为当日从 `01` 开始的两位序号。

## 9. 研究任务模板

当前实现可以为每个账号建立一个只包含其对应设备的本地 `deviceGroup`，再复用既有任务接口：

```json
{
  "schemaVersion": 1,
  "taskId": "ramp-account-01-20260714-01",
  "mode": "research_read_only",
  "topic": "夏季通勤穿搭",
  "seedKeywords": ["夏季通勤穿搭"],
  "sources": ["search", "suggestions"],
  "deviceGroup": "account-01-research",
  "commentMode": "none",
  "interactionPolicy": "human_final",
  "budgets": {
    "wallClockSeconds": 600,
    "maxQueries": 2,
    "maxNotes": 5,
    "maxNotesPerQuery": 3,
    "maxResultScrollsPerQuery": 2,
    "maxNoteScrolls": 1,
    "maxCommentPanels": 0,
    "maxCommentsPerNote": 0,
    "maxNoNewScrolls": 1
  },
  "aiPolicy": {
    "topicPlanner": true,
    "pageFallback": true,
    "resultAnalysis": false,
    "maxAutomaticCalls": 2
  }
}
```

第 4 天以后可以在人工批准后提高研究预算，但不得添加互动字段；正式执行前仍应先做 `DryRun`。

## 10. AI 介入规则

| Agent | 触发条件 | 上限 | 输出 |
| --- | --- | --- | --- |
| 主题策划 | 新主题已取得真实建议词且无有效缓存 | 每个新主题 1 次，缓存 30 天 | 意图组、排序查询、排除词 |
| 页面恢复 | 本地指纹和两次本地 OCR 均无法恢复 | 每任务最多 2 次 | 页面类型、证据、语义目标；无坐标 |
| 研究分析 | 至少取得 5 条去重候选 | 每任务最多 1 次 | 聚类、相关性、内容缺口、理由 |
| 评论辅助 | 人工主动选中候选并请求 | 按人工请求 | 一条可编辑草稿，不填写、不发送 |

自动模型调用总数不得超过任务中的 `maxAutomaticCalls`，且硬上限为 4。登录、验证码、权限、订单、账号隐私、私信、联系人和支付画面禁止上传模型。

## 11. 人工检查点

以下事项必须暂停自动流程并由人工处理：

- 首次登录、短信验证、验证码、身份验证、风险提示和账号申诉。
- 头像、昵称、简介、背景图或其他账号资料变更。
- 点赞、收藏、关注、评论、回复、私信、分享、购物、支付、发布和删除。
- 任何内容版权、商业宣传、抽奖、医疗、金融或其他高风险内容判断。
- 中文输入回显不一致、页面置信度不足、候选身份无法唯一确认。
- 设备或网络需要本地变更时，另行取得本次会话的明确授权和回滚方案。

人工互动交接仍遵循：选中单条候选 → 效卫只显示一台手机 → 确认群控同步关闭 → 脚本导航并暂停 → 人工核对后自行操作。

## 12. 失败与熔断

- 正式研究工作单元中，单台设备连续两次设备失败：隔离该设备，并保留实际生成的本地截图和 UI 层级路径。
- 正式研究工作单元中，两台设备出现相同失败签名：全局熔断，停止向其他设备扩散；主题发现不继承该计数。
- 登录、验证码、风险提示、支付、私信、联系人或权限挑战：立即停止全部相关动作。
- 设备离线：未开始的工作单元最多重新分配一次；账号级单机任务直接转人工或暂停。
- 来源入口不存在：只跳过该来源，不判定账号或设备失败。
- 效卫 API 返回成功：仍需 ADB/UI 后验验证；API 未验收时保持禁用。

## 13. 数据与运营指标

建议记录：

- 任务完成率、人工接管率、设备隔离次数和失败签名。
- 每个主题的查询数、候选数、重复数、人工采用数和内容缺口。
- AI 调用次数、缓存命中率和 0 模型任务比例。
- 账号阶段、最后一次人工复核时间和暂停原因。
- 已发布内容的人工记录及公开表现数据；不得通过自动互动影响数据。

不记录：密码、验证码、真实设备序列号、联系人、私信内容、支付信息和未经脱敏的敏感截图。

## 14. 验收标准

- 自动执行中不存在点赞、收藏、关注、评论发送、私信、发布、删除和支付。
- 登录、验证码、风险和权限页面的停止率为 100%。
- 每个账号和设备都使用本地不透明别名，Git 中没有真实标识。
- 所有研究任务按 `taskId` 幂等，相同任务不会重复操作设备。
- 已标定页面可以 0 次模型调用；自动 AI 调用每任务不超过 4 次。
- 每台设备独立解析页面，不共享坐标或主控点击。
- 人工互动前必须完成单机显示和群控同步关闭确认。
- 不执行随机停留、虚假互动、伪造轨迹、切换身份或其他规避平台控制的动作。
- 阶段升级具有人工批准记录，并由研究质量和安全结果驱动，而不是机械行为数量驱动。

## 16. 实际效果实验设计

### 16.1 “有效”的可观测定义

小红书没有向本项目公开一个可直接读取的“账号权重”字段，因此不能用“权重提高了”作为未经证实的结论。实验只观察以下指标：

| 指标 | 计算方式 | 用途 |
| --- | --- | --- |
| 推荐主题准确率 `FeedPrecision@20` | 推荐流前 20 条中，与目标主题相关的条数 / 20 | 判断推荐内容是否逐渐垂直 |
| 搜索建议覆盖率 `SuggestionCoverage@10` | 前 10 个建议词中，属于目标主题词表的比例 | 判断主题学习是否稳定 |
| 搜索结果相关率 `SearchPrecision@10` | 固定关键词前 10 条结果中的相关比例 | 排除搜索入口自身波动 |
| 候选采用率 | 人工采用候选数 / 去重候选数 | 衡量研究是否真正帮助内容策划 |
| 账号公开指标变化 | 粉丝、获赞与收藏的日/周差值 | 只做结果记录，不单独证明因果 |
| 人工发布表现 | 人工记录发布后 2h、24h、72h 的公开表现 | 需要人工发布和回填，自动化不发布 |
| 安全事件率 | 风险页、验证码、异常验证、导航熔断次数 / 任务数 | 任何增长都优先处理，不用增长指标抵消 |

账号主动点赞或收藏了多少，不等于该账号获得了多少曝光。因此互动动作只作为实验条件，最终主要看推荐主题准确率、内容表现和安全事件。

### 16.2 三设备七天对照实验

完成稳定别名和账号映射后，把三台设备分成三个固定组。每组只有一台设备和一个账号，不在实验中交换设备。三台设备必须分别独立通过 Hermes 只读能力验收，不能以其中一台的结果代替其他设备。

| 组别 | 每日自动部分 | 人工部分 | 评论 |
| --- | --- | --- | --- |
| A：对照组 | 1 次只读主题研究 | 不安排实验互动 | Dry Run 关闭 |
| B：点赞组 | 与 A 相同 | 从审核队列中人工确认最多 2 条高度相关候选并自行点赞 | Dry Run 关闭 |
| C：收藏组 | 与 A 相同 | 从审核队列中人工确认最多 1 条具有长期参考价值的候选并自行收藏 | 只生成最多 1 条 Dry Run 草稿，不填写、不发送 |

实验约束：

- 所有组使用同一个目标主题、相同的查询预算和相同观察时间。
- 实验前优先把三台设备统一到同一已验证的小红书版本；如果客观上无法统一，必须把 App 版本记录为混杂变量，报告按版本分层，不直接把跨版本差异归因于实验条件。
- 点赞或收藏前必须完整进入候选详情、核对笔记身份，并由人工判断内容确实值得该动作。
- 不使用随机时间、批量点击、相同内容复制评论或跨设备同步互动。
- 每天只运行一个实验窗口；同一候选不得跨天或跨组重复计入。
- 若出现登录、验证码、风险提示、权限挑战或页面身份不确定，当天该设备实验立即结束。
- 组别先固定运行 7 天；由于每组只有 1 个账号，结果只能视为小样本趋势。需要重复两轮或增加样本后才能增强结论。

### 16.3 观察时间线

| 时间 | 工作 | 产物 |
| --- | --- | --- |
| D0 | 主页指标、20 条推荐、固定搜索建议和固定搜索结果基线 | `baseline.json` |
| D1-D7 | 每日一次同预算研究；B/C 组由人工执行批准动作 | `daily-observation.jsonl`、人工审核记录 |
| D3 | 中期检查，只排查采集和安全问题，不临时更改组别 | `checkpoint-d3.json` |
| D7 | 重复 D0 测量 | `endpoint-d7.json` |
| D8 | 计算组内前后差值和组间差异 | `effect-summary.json` |
| D9-D15 | 可选第二轮，保留对照并更换 B/C 实验条件 | 第二轮产物 |

### 16.4 初步判读规则

- `FeedPrecision@20` 相比 D0 提高至少 20 个百分点，且连续两次观察方向一致，记为“主题推荐有改善迹象”。
- 实验组改善幅度高于对照组，且第二轮仍同方向，才记为“互动条件可能有关”。
- 只有公开粉丝或获赞收藏变化，而推荐主题准确率和内容表现没有改善，不判定“养号成功”。
- 出现任何新增安全事件时，实验结果标记为无效并暂停，不通过降低采样标准继续运行。
- 样本不足、页面规则变化或人工执行不一致时，结论固定为 `inconclusive`，不强行得出有效或无效。

### 16.5 评论 Dry Run

评论策略不连接输入框，只产生本地计划事件：

```json
{
  "mode": "dry_run",
  "candidateId": "candidate-local-id",
  "strategy": "specific_and_relevant",
  "draftGenerated": true,
  "wouldFill": false,
  "wouldSend": false,
  "reason": "人工选中候选后测试草稿质量"
}
```

评估草稿是否具体、与原内容相关、没有联系方式或夸张承诺；不以评论数量为指标。
