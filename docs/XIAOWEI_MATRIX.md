# 效卫矩阵执行说明

效卫用于设备投屏、分组展示和人工接管。生产设备动作的唯一公开入口是 `xhs.cmd`；Hermes 和操作者都不能直接调用效卫私有接口、WebSocket、内部脚本或裸 ADB 发送设备动作。

## 设备选择

- 使用唯一两位机器编号和可见机器名称描述手机。
- 任务只验证本次选中的设备和本次动作需要的能力。
- 其他在线、离线或能力降级的设备不是目标任务的阻塞条件。
- 自动选择空闲测试机时按本地配置的稳定优先级选择一次，并在计划确认前冻结；确认后不自动换机。
- 每台设备保持独立身份、布局、App 版本、锁、任务、checkpoint 和证据范围。

## 执行通道

```text
xhs.cmd
→ xhs.ps1
→ scripts/xhs-agent.mjs
→ 受控 PowerShell/Node 工作流
→ 语义设备适配器
```

效卫 API 只有当前 catalog、测试、现场预检和已接受 capability profile 同时证明可用的语义能力才能路由。候选 JSON、旧文档或 API 返回成功都不能单独证明动作可用；设备状态必须由新鲜 UI 后验验证。

## 并发

任务可选择任意有限机器列表，但实际设备数、并发、动作和吞吐必须落在当前人工接受的 capability profile 内。限制来自当前实测能力，不是永久仓库业务上限。父进程分配不可转移的 worker ticket 和执行槽；等待 worker 没有设备权限。

普通只读导航失败只停止对应 worker。验证码、风控、身份漂移、计划/审批不匹配、父租约丢失、证据或预算损坏、禁止动作、人工中断以及不明确账户状态会打开全局熔断。

## 文本与人工接管

文本输入只在已验证安全编辑框、已接受输入通道和精确回显验证下使用。登录、验证码、权限、支付、发布、评论发送、私信、关注和账号设置由人工在手机上最终处理；自动任务不得通过通用点击或文本原语代替人工边界。

运行前后使用 `xhs.cmd repo status --json` 记录电脑、仓库路径、分支、commit 和未提交数量，避免 Hermes 猜测代码位置。
