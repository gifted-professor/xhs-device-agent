# 效卫矩阵执行说明

效卫用于设备投屏、分组展示和人工接管。Agent 默认使用命名 HTTP API；`xhs.cmd`、项目适配器和开发/兼容命令按任务能力使用，不再把单一入口写成全局限制。

## 设备选择

- 使用唯一两位机器编号和可见机器名称描述手机。
- 任务只验证本次选中的设备和本次动作需要的能力。
- 其他在线、离线或能力降级的设备不是目标任务的阻塞条件。
- 自动选择空闲测试机时按本地配置的稳定优先级选择一次；任务已指定机器时不擅自替换。
- 每台设备保持独立身份、布局、App 版本、锁、任务、checkpoint 和证据范围。

## 执行通道

```text
named HTTP API / xhs.cmd compatibility
→ scripts/xhs-agent.mjs
→ PowerShell/Node adapters
→ semantic device operations
```

命名 HTTP 为默认通道；命名能力缺失时可转入项目已有的效卫适配、开发或兼容通道完成任务，并把稳定做法补成命名能力。候选 JSON、旧文档或单次 API 返回成功不能单独证明后态；设备状态仍由新鲜 UI 或截图证据验证。

## 并发

任务可选择任意有限机器列表和并发。capability profile 描述正式复合执行器的当前实测范围，不阻断命名 HTTP 或原子能力。使用正式执行器时，父进程仍可分配 worker ticket 和执行槽提供恢复能力。

普通导航失败只影响对应 worker。当前请求明确包含的登录、验证码、权限、互动或账号状态动作可继续，不因计划、审批、白名单或能力档案追加拦截。身份尚未唯一绑定、父租约丢失、证据损坏或发送结果不确定时只冻结受影响范围，重新观察或切换项目适配路线；不得盲目重发。

## 文本与人工接管

文本输入优先在可验证编辑框中使用并检查回显。发布、评论、私信、关注和账号设置在用户明确请求且已有实现时可以自动执行；重复缺口应实现为可验证高层能力，而不是形成永久策略拒绝。

运行前后使用 `xhs.cmd repo status --json` 记录电脑、仓库路径、分支、commit 和未提交数量，避免 Hermes 猜测代码位置。
