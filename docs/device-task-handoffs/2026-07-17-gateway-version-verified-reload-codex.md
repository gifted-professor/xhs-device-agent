## 根因与修复

共享网关旧进程持续健康并不代表当前磁盘代码已加载。原健康响应没有构建或启动实例身份，管理脚本也没有证明新启动 PID 就是 17891 的监听者，因此旧健康响应可能造成假成功，PID 文件也可能与真实监听者漂移。

现已增加版本验证生命周期：健康响应提供 `buildId`、`bootId`、`accepting` 和队列深度；重启优先通过本地密钥认证的 loopback 接口停止接收新请求并排空队列。替代进程只有在 PID 持有 17891、启动身份已变化、构建身份匹配当前源码且恢复接收请求后才会写入 PID 文件并报告成功。

计划任务保留当前用户的 Interactive/Highest。组合启动脚本仍需修改效卫私有 API 的系统配置，因此没有采用降权或无界强杀方案。

## 维护用法

```powershell
.\xhs.cmd remote status
.\xhs.cmd remote restart
```

`status` 的 `health: true` 只代表服务可响应；判断代码是否新鲜必须同时查看 `codeCurrent: true`。`restart` 若无法排空、端口被未知进程占用、新进程未持有端口、启动身份未变化或构建身份不匹配，会失败关闭且不伪造 PID。
