# 共享网关按设备并发修复交接

日期：2026-07-17  
执行者：Codex  
机器分工：04 为 Codex 默认测试机；01 保留给 Hermes；本次跨设备并发仅使用 02、03。

## 根因

共享网关在 HTTP 层使用单个 Promise 队列，导致所有设备命令全局串行。`xhs-agent` 的 CLI 入口确实使用同步子进程，但网关自身通过异步 `spawn` 创建相互独立的 CLI 子进程；因此跨设备并发的实际阻塞点是网关调度器，而不是子进程创建方式。

## 修复

- 同一两位机器号共用一个串行作用域，严格保持到达顺序。
- 不同机器作用域可同时启动，不共享节点、状态或后态证据。
- 不带唯一机器号的命令作为公平全局屏障；它等待在先设备工作，执行时独占，排在它之后的设备请求不能插队。
- 总容量仍为 16，包含运行中和等待中请求。
- `/health` 新增聚合 `activeRequests`，配合 `queueDepth` 验证真实并行，不公开机器身份。
- 认证排空会等待所有机器作用域和全局屏障清空后再关闭端口。
