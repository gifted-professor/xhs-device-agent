## 5. 微信钱包案例（核心证据）

### 5.1 目标
读取 03 号机微信钱包余额。

### 5.2 执行路径

```json
POST /v1/command
{ "command": "app.open", "machine": "03", "package": "com.tencent.mm" }
```

### 5.3 关键现象

1. **应用成功打开**：`ok=true`；
2. **当前 Activity 为 `MallIndexUIv2`**；
3. **`device.ui` 返回空 XML（仅 382 字节）**：微信对无障碍服务做了保护，底部 tab「我」都未暴露；
4. **`device.screen` 截图成功**：返回 1080×2400 PNG，约 533 KB；
5. **结论**：能看到图，但无法自动从图中识别元素并点击。

### 5.4 失败尝试记录

| 尝试 | 命令/方法 | 失败原因 | 证据 |
|---|---|---|---|
| 1 | `device.tap-text` | UI 层级为空，找不到「我」 | 会话日志 |
| 2 | `device.tap-ocr` text="我" expectText="服务" | 本地 OCR 未返回两个稳定目标 | 请求 ID: `cc245371-41df-4291-900e-234abaa4ebaf` |
| 3 | `wechat-wallet-balance`（横线） | 命令名错误，未实现 | 请求 ID: `2a4cd550-1ffc-49dc-8023-dd927845ab6b` |
| 4 | `wechat.wallet-balance`（点号） | ⚠️ 已实现但 OCR 失败 | 请求 ID: `8018070a-7fd3-4745-9833-ea83ae0617e8`，错误：`Local OCR did not produce two stable unique WeChat change-page marker matches` |
| 5 | 安装 `rapidocr-onnxruntime` | CPU 不支持 AVX，DLL 初始化失败 | 终端输出 |
| 6 | 安装 `onnxruntime==1.13.1` | Windows 无此版本发行包 | 终端输出 |
| 7 | 安装 `tesseract` | 需要管理员权限，未继续 | 会话日志 |

## 7. Hermes 视觉配置状态

### 7.1 当前配置

```yaml
auxiliary:
  vision:
    provider: kimi-coding
    model: kimi-k2.5-vision
    base_url: https://api.kimi.com/coding
    api_key: ''
```

### 7.2 问题

- 主模型 `kimi-k2.7-code`（provider `kimi-for-coding`）能工作；
- 但 `vision_analyze` 工具无法复用该凭据；
- 日志显示 `kimi-coding` 被解析为 `AnthropicAuxiliaryClient`，存在 provider 映射问题；
- 当前环境没有可用的本地 OCR（AVX 缺失 / Tesseract 未安装）。

### 7.3 下一步

- 方案 A：用户提供 Kimi API key，写入 `.env` 后重启 Hermes；
- 方案 B：安装 Tesseract OCR（需要管理员权限），配置项目使用；
- 方案 C：修复 Hermes 的 `kimi-coding` provider 映射问题（需要改 Hermes 源码）。
